## Blocking source findings and minimal fixes

### B1 — native dictionary call is rejected

Evidence: `S/span_refinement_model.py:41-44` declares `forward(self, **inputs)` and calls `self.parent(**inputs)`. The supplied parent declares `forward(self, inputs)` at `P/pv_ground.py:355`. The established native observation path calls `model(dict(inputs))` at `R/readback_preflight_checks.py:42`, also used by `T/paired_support_loop.py:70-75`.

This is a concrete call-signature incompatibility. The new wrapper rejects that existing positional dictionary before entering its body. Unpacking the actual dictionary into its keyword-only entry instead causes the parent to receive keys such as `points` rather than its single `inputs` argument. Calling the wrapper with the special keyword `inputs=...` would work, but that is a changed call contract and does not match the supplied native caller.

The verifier reproduced the positional binding failure using Python's `inspect.Signature`, without invoking a model: `TypeError: too many positional arguments` (`DIAGNOSTIC_VERIFICATION.json`).

**Minimal fix:** use `forward(self, inputs)` and the single call `self.parent(inputs)`. Keep the existing no-grad scope and subsequent mixer application. This preserves the native API and the intended one-parent-forward behavior.

### B2 — source-mode checkpoint identity is missing

Evidence: `S/extremal_span_mixer.py:17-18` stores `source_mode` as a plain string, and `:69-72` uses it to select the different source set. The architecture has the same 14 parameter tensors in either mode (`:19-27`), with no registered mode buffer, extra state, or checkpoint helper. `S/span_refinement_model.py:36-38` constructs a mode and checks only tensor count. The proposal requires a real save/restore witness at `S/METHOD_PROPOSAL.md:46`, but no implementation currently binds restored weights to a mode.

Consequently, the 14-tensor weight dictionary is insufficient to reconstruct which arm was saved. Loading those same compatible tensor keys into an opposite-mode constructor would not identify the semantic mismatch. This is a static conclusion, not a claim that an existing checkpoint has actually been corrupted. PyTorch v1.10.2 saves parameters, persistent buffers and explicitly implemented extra state; it does not automatically include this plain string. [Official v1.10.2 Module source](https://raw.githubusercontent.com/pytorch/pytorch/v1.10.2/torch/nn/modules/module.py), cached raw lines 1249-1270.

**Minimal fix:** provide an explicit head checkpoint payload containing `source_mode` and the 14-tensor `state_dict`, and a restore path that validates the expected arm and reconstructs/loads using the saved mode. No added trainable capacity is needed. Preserve the 29,793-parameter/14-trainable-tensor arithmetic. Actual optimizer and same-output restoration remains a later M0 requirement after the active job closes.
