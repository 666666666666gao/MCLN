# 固定参数的 BatchNorm 运行统计诊断

本项是只读诊断，不是新模块、训练结果或第二套部署评分。当前 source_conditioned 的三轮原生训练配置保持不变；独占 A100 的活动训练结束并完成保存恢复检查后，才允许诊断占用 GPU。随后再串行进行相同预算的 without_additional_source 正常训练。

## 已有问题证据

- 当前 E0：5677/4920；完整 E1：5645/4599，下降 32/321 条。历史 C-off E1 为 5644/4604，只作历史参照。
- 历史 C-off E0/E3 状态比较：1295 项中 1071 项改变；252 项 BatchNorm 运行缓冲区改变，另外 819 项也改变。状态差异不能证明退化原因。
- CPU 构造模型已验证只替换运行均值、方差及计数，不改 affine、Linear、LayerNorm 参数；尚无本模型 GPU 干预结果。

## 唯一干预

从同一训练终点加载全部参数，在同一模型、eval/no_grad 下，对每份实际验证输入依次运行：A 使用训练终点的 BatchNorm 缓冲区；B 使用从官方 PV/G/A/B 原生工厂重建的 E0 缓冲区。B 保留 A 的全部已训练参数，包括 BatchNorm affine 参数。两次前向之间恢复 Python、NumPy、Torch CPU/CUDA RNG；DataLoader 每个 batch 只读取一次，分支使用独立深拷贝。

复用实际训练的 TrainTester._main_eval_branch 和 GroundingEvaluator。部署口径仍为 last/bbs；原生完整评估函数同时计算原来的框和 Mask 指标。已有 native_root_bbs 只用于逐行诊断，并将其命中数与原生 evaluator 严格核对。保留全部 256 候选参与前向，记录其几何上界；不裁剪低分候选，不新增排名。

结束后恢复训练终点缓冲区，逐项确认完整模型状态没有改变。无优化器更新、无新权重输出、无对活动源码或训练状态的修改。

## 执行顺序与范围

1. Fresh source review，然后在当前三轮训练结束、GPU 锁释放及完整恢复检查完成后，用真实第一个 batch 做 8 条两分支预检。
2. 预检确认原生指标和逐行指标一致、缓冲区替换及完整状态保持后，再运行完整 9508 条/1189 batches 两分支对照。预计约 60 分钟，依据实际预检吞吐修正；首查放在预计完成前几分钟，后续间隔 240 秒。
3. 记录两阈值净变化、修复/破坏、所选 Query 变化、Full-256 覆盖及同 Query 框/Mask情况。只保存紧凑逐行 JSONL 和摘要，不新建巨型候选缓存或权重。

诊断输入是独立重放的完整验证集，不承诺与训练内 E3 的随机点采样逐位一致；A/B 之间输入和 RNG 配对。因此不覆盖历史正式成绩，不自动晋升 B 为最好权重。即使 B 改善，也只说明固定检查点下运行统计的前向作用；必须进一步通过正常训练对照验证保持统计的配方，才能形成方法收益结论。
