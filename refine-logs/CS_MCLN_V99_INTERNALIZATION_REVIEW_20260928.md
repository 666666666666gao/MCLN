### G1. The fixed12 audit cannot currently provide the promised gradient-scale evidence

Its later quality losses at lines 164-169 therefore have no model or semantic-logit gradient graph, and the script never calls the native total criterion or `autograd.grad`. The two-step preflight does not replace that evidence: `scripts/train_cs_mcln_scanrefer.py:281-282` accepts any finite auxiliary value, including zero, and lines 318-320 inspect a gradient from the **total** loss. Native final-layer CE alone can produce that readback-output gradient even if the quality objective is not exercised by those particular random batches.

**Minimal viable correction, confirmed against the current interfaces:** retain both values from `TrainTester.get_criterion(config)` and keep the single existing model forward. Outside `no_grad`, replace only `output['last_sem_cls_scores']` with a detached `requires_grad_(True)` leaf. Call `TrainTester._compute_loss(output, criterion, set_criterion, config)` using the native audit configuration, whose quality weight is zero. Compute `autograd.grad(native_loss, leaf_logits)`; recompute the inexpensive `compute_default_source_scores` graph for each quality temperature and obtain the corresponding quality-only logit gradient. Record the native loss, unweighted quality losses, finite gradient norms and their scales on the same fixed12 rows, together with the existing active-root/eligible-candidate counts. This requires no second model forward or optimizer. The native criterion includes the actual ScanRefer final-CE scaling, `0.5 / 7`, rather than an unscaled surrogate (`models/losses.py:4061-4086`). The relevant entry points are `main_utils.py:5190` and `main_utils.py:6656`.

These are **eval-mode semantic-interface gradients**. They help calibrate the auxiliary weight but do not establish full train-mode parameter gradients. For that separate existing preflight gate, before total backward, compute quality-only `autograd.grad` into `model.cs_geometry_readback.output.weight` with `retain_graph=True` when a nonzero quality comparison is present. Record its finite/nonzero result. A batch with no active comparison should be recorded as not exercising this check; do not force arbitrary first batches to contain qualifying roots. If neither step exercises it, that particular quality-propagation evidence remains pending, rather than being inferred from the total-loss gradient.

## Intentional limits and remaining evidence

This is a three-role internal Query-Mask support readback plus a **limited matched-root/background ranking control**. It does not migrate the seven V99 geometries, fused-mask geometry, version loss, multi-qualified-candidate supervision, G label replacement, or teacher parameters. The contrastive projection and final Query-Mask path still use the pre-readback Query (`models/mcln.py:2109-2116,2152,2211`), as intentionally specified. None of these limits is reported as an accidental omission or a blocking defect.

Excluding a row/Query from the quality score list means zero **direct** derivative with respect to its excluded score. It does not isolate all upstream feature/parameter gradients: the intended set attention and native semantic-head BatchNorm share information. The synthetic mixed-batch tests establish the former, not the latter. This does not warrant changing the native BN architecture.

The current ScanRefer loader constructs grounded annotations with an integer target object; it does not construct a no-root negative-expression branch (`src/joint_det_dataset.py:633-649`). ScanNet's detection prompts, including absent-category words, are excluded by source. No speculative negative-expression compatibility branch is required. A future genuinely no-target dataset would need a separately specified contract before reusing the root assertion.

The fixed12 audit deliberately contains only ScanRefer rows with one valid root. It cannot by itself validate real mixed-loader exclusion or other-instance matching; current synthetic tests cover those direct eligibility rules. The existing preflight provides actual mixed training batches, zero-update output comparisons, finite total loss/norm, M3 support gradients, and resource/save measurements, but its current zero-update comparison is eval-mode on one validation example and its current readback check is only the output projection. Do not expand those facts into broader completed validation.

After the small G1/G2 corrections, one bounded re-review of the changed audit/preflight seams is appropriate. Formal work still waits for the native21 control and full9508 diagnosis, then the fixed12 training-only calibration, actual quality-propagation/zero-update/resource preflight, and the existing storage budget check.
