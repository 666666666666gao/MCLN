# Nr3D/Sr3D真实点云到PV体素的CPU接入检查

本检查服务于ScanRefer正式晋级后的Nr3D/Sr3D接续。只验证已有原生数据层与固定作者体素预处理之间的接口，不训练或加载模型，不接入当前ScanRefer进程。

## 固定范围

- 复用此前已经固定、未按模型结果选择的32条训练输入：每个数据集12条语言表达、4条ScanNet联合检测样本。
- 使用已修复的625-file原生数据源、mesh superpoint及`butd_cls`对象输入，不重新启用旧视角增强代码。
- 每条分别关闭/开启已有训练增强，随机种子为2027加固定行索引，共64次真实`__getitem__`。
- 每次同一输入分别经过作者train/test体素处理器，共128次调用；按4行构造16批。
- 固定作者2厘米体素、每体素最多5点、最多50000体素，范围为`[-8,-8,-0.2,8,8,3.8]`。配置仅启用体素化，不启用范围裁剪、打乱或额外采样。
- CPU单线程、`CUDA_VISIBLE_DEVICES`为空，复用已验证的PV运行环境。

原有固定选择帮助函数只用于选取这些真实输入；旧外观分支、缓存向量及其权重不参与。

## 逐项验证

真实输入保持50000×6的XYZ和RGB。用独立NumPy float32量化、稳定分组及每组前五点计算，核对作者实际`Point2VoxelCPU3d`输出的全部坐标、有效点数与六维点值。量化使用float32是已有运行时witness确认的数值协议，不用float64在边界上改变分箱。

同时检查完整点数组的内容和顺序未改变，体素坐标批次前缀为`[batch,z,y,x]`，原生对象框、预测类别、有效槽和superpoint在批处理后保持一致。`butd_cls`对象框与场景实例框的对应也逐样本核对；这不是纯预测框输入协议。

单独记录：输入范围外点数、有效体素数、体素存储点槽数、由于每体素五点上限舍弃的点数。对于语言行，使用训练标注仅统计root目标点的保留情况；它不进入体素处理器或模型输入。

“保留原始点数组”与“所有点都编码进体素”是两个不同判断。体素范围外点仍可存在于完整点数组。root点槽数也不能直接等同于目标特征质量或REC候选覆盖；邻域及后续特征聚合尚未在此执行。
