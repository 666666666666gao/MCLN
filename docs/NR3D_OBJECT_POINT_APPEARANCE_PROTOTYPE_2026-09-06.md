# 真实对象点外观原型：为现有对象记忆补充视觉输入

这是等待C1终态期间独立准备的REC方向原型，不是C1的新增模块，也不是已验证新模型。
当前原生对象记忆只拼接128维框位置和160维预测类别编码。R1扩大了可访问记忆轴，
但没有给对象增加真实局部外观；本原型直接编码同一50,000点输入里的框内彩色点。

## 编码与接入

对原协议有效对象框逐一使用原始float32边界裁剪，不扩框、不使用GT实例成员清洗。
每个点拼接按框半尺寸归一的局部XYZ和原生输入RGB，经6→64→64的共享MLP，
对裁剪成员分别mean/max pooling，拼接128维后映射到288维。输出投影为零初始化。
总41,472参数、5张量；没有新的PointNet++/体素主干、固定点数采样或文本解析输入。

残差只加入最后一层Decoder的detected_feats，调用原有cross_d注意力及后续网络。
前面的场景编码、seed和Query采样以及前五层Decoder不改；在非零残差下，最后一层
Query、语义分数、Box和Mask都允许变化。这项直接影响原生网络，不能声明REC保持。
正式合法性过滤与两种语义评分路径必须一起核验，不能只看某个额外头loss。

原型文件`scripts/nr3d_object_point_appearance.py`独立于冻结源码；attachment移除后
恢复最后一层原forward。没有新的Source Selector、候选对重排或Parent Gate。

## 已有证据与输入边界

既有16行输入审计中683个有效对象槽均有框内采样点、框各轴为正；本原型据此采用
明确的非空裁剪合同，遇到违反合同的有效槽会停止，不借用其他物体或远处点。
这16行不证明完整fit/holdout或其他数据集都没有空裁剪，训练前须扩大输入检查。
padding槽保持零残差。683槽中123个裁剪的真实实例点不足一半，mean/max并不保证
消除这类污染；GT成员信息仅在既有报告中用于诊断，不进入本模块。

原服务器Py3.7/Torch1.10环境的4个CPU合成测试已通过：零初始化与梯度、框内外颜色
作用、点/对象/批次索引和坐标平移对应、仅最后一层接入及原方法恢复。
CPU证据`refine-logs/object_point_appearance_cpu_20260906_v1/`。

下一步独立CPU真实输入检查固定同16行/683槽：对点hash、box和裁剪点数逐一核验，
运行零输出和固定扰动共32次appearance forward，检查有效外观、padding和恢复。
这不运行MCLN主模型，不使用GPU、不更新参数、不读取模块留出或正式验证行。
入口`scripts/probe_nr3d_object_point_appearance_inputs.py`。

真实原生Decoder预检、完整输入覆盖检查、训练控制与质量筛选仍未完成。
