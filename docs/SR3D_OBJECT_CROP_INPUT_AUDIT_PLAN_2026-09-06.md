# Sr3D训练对象裁剪输入检查

协议核对确认Sr3D训练有效65846表达、1018扫描、490物理空间。468个扫描与已完成
的Nr3D对象裁剪审计重叠，550个扫描未在该审计中。正式Sr3D为17726表达、255扫描、
123空间；本次只检查训练输入，不运行正式模型评估。

每个Sr3D训练扫描固定取CSV过滤后的首条表达，通过原生Joint3DDataset读取同50000
XYZ/RGB点、既有butd_cls对象框和有效槽；augment=False。不开新点采样或GT实例mask
清洗，不修改当前对象外观模块，0模型forward、0GPU、0优化器更新。

468个共同扫描核对实际Sr3D点Tensor、所有输入框和有效对象索引与Nr3D审计逐字节相同，
同时锁定完全相同的box_crop_mask文件。满足这些条件才复用已完成的裁剪计数合同。
550个新增扫描实际执行当前Torch裁剪，并与NumPy显式AABB边界逐点比较。两种检查
方式分别计数，不能写成1018个扫描全部重跑了裁剪。

记录全部对象槽、裁剪点数、非正轴和空裁剪案例。检查失败保留具体输入证据，不增加
容差、扩框或fallback。锁定源码、数据、Nr3D审计及当前协议核对receipt，结束后复查。

入口scripts/audit_sr3d_object_crop_inputs.py。使用原Py3.7/Torch环境、CPU两线程，
独立目录和日志，与Nr3D GPU学习并行读取输入。初估约7–9分钟，首次观察在5分钟后，
随后240秒。这只补齐Sr3D输入覆盖，不恢复缺失的Sr3D权重，也不自动启动Sr3D训练。
