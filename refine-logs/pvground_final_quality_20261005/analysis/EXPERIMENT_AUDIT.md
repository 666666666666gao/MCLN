## B. Native scoring, loss and metric denominators — PASS

Native bbs is token **softmax** probability summed over the binarized main-positive map, plus raw modifier/pronoun/relation maps, minus the other-entity map (`runtime_bundle/native_root_bbs.py:4-9`). It is signed expression evidence, not a binary class probability. This matches the pinned native evaluator (`NATIVE/src/grounding_evaluator.py:218-281`, `:535-553`). The evaluator counts strict threshold hits and increases its GT denominator by the number of evaluated root objects (`:296-303`); the report divides hits by row count (`analyze_closed_formal.py:79-82`). No metric is normalized by the maximum, minimum or mean of predictions. Feature/attention normalizations inside the model are not accuracy denominators.

The new target is IoU between **detached final deployed Boxes** and detached dataset root Boxes, with intersection/union geometry (`runtime_bundle/native_final_quality.py:19-29`). For each pool, it minimizes the sample mean of the within-pool variance of `native_bbs - final_iou` (`:33-44`). This equals half the mean ordered-pair squared difference. Its direct score derivative is `2*(error_i - pool_mean_error)/(batch_size*pool_size)` inside the pool and zero outside. That direct-logit statement does not imply shared readback parameters can never change nonpool Query scores after an update.

The actual native final matcher is `matching[1]`: native calls occur in `proposal_, last_, 0head_, …, 4head_` order and preserve valid GT slot zero (`NATIVE/models/losses.py:817`, `:852-885`, `:891-917`). Original G still replaces the eos-weighted CE of the qualified unmatched pool using `num_boxes`, multiplied by `.5/7` (`runtime_bundle/pvground_semantic_assignment.py:34-50`). Native CE and contrastive reductions remain unchanged (`NATIVE/models/losses.py:484-511`, `:776-778`, `:943-956`). The new arm adds only `1.0 * quality` to `native + correction`, with the same AdamW, clipping and budget (`runtime_bundle/run_final_quality_fit.py:460-470`). The control runner diff and 15 inherited helper hashes confirm this source-level comparison.

The real two-update preflight receipts contain zero pairwise-loss error, logit-gradient errors at most `7.28e-11`, zero nonpool direct gradients, correct equal-score quality direction, detached geometry, and isolated quality gradients reaching the readback output immediately and earlier readback modules after the first update (`complete/preflight/preflight.json:24-274`; executable witness `runtime_bundle/native_final_quality.py:56-104`). These are executed-receipt evidence, not newly replayed tensor checks. The first/last 100-step quality-loss means are 0.007576918 and 0.006647891; this reduction is explicitly **training loss**, not accuracy or proof of efficacy (`analysis/AUDIT_CPU_CHECK.json:49-54`).
