# Nr3D 原生 Mask 与点细节记忆的独立配对短训

本计划在读取本实验的任何训练后留出结果之前固定。此前 L1 已完成且质量筛选失败；
16 行点细节 CUDA 预检通过。此实验验证用户提出的高分辨率局部记忆路线中的点式控制，
保留 PointNet++ 全局路径及同一份 50,000 点输入，不是体素主干替换。

## 两臂与唯一结构增量

| 项目 | A：native | B：detail |
|---|---|---|
| 起点 | 同一受保护 Nr3D 权重 | 相同权重，新增输出矩阵为零 |
| 原生可训练参数 | x_query、x_mask、rel_encoder，16 个张量，1,348,960 参数 | 完全相同 |
| 新局部读取 | 无 | SA1 的 2,048 点特征插值至原始采样点，拼接 SP 内相对坐标与 RGB，点编码后按真实 SP 成员平均 |
| 新参数 | 0 | 54,144，3 个张量；合计 1,403,104 |
| 原邻域、Mask 头、损失 | 保持 | 保持；残差加入原两个邻居的特征 |

两臂其余参数及所有模型 buffer 冻结，使用 model.eval 保持原生确定性；参数梯度仍启用。
框、Query 身份、候选得分和选择路径必须一致。新增分支无 GT 实例 Mask 输入，
不改变候选规则，不加入任务 token、对象外观模块或新损失。

这不是等参数容量对照。B 比 A 多约 4.0% 可训练参数；若通过，只能先说明这项局部
记忆增量有效，不能单独证明提升全部来自分辨率。现有 SA1 特征仍来自同一输入；
插值不会恢复扫描中不存在的点。

## 固定数据与更新预算

- 沿用已有按 scene 哈希的 fit/holdout 划分；fit 取 CSV 顺序前 2,048 条，262 个场景。
- holdout 为 6,172 条、98 个场景，未参与新增参数训练，但冻结主干以前见过这些场景。
  它是模块留出筛选，不能当作完整系统的新场景泛化或正式验证成绩。
- 与 M5 的规模相同，但不复活 M5 最近邻分支。所有 724 个输入文件、612 个冻结源码
  文件、parent 权重及本实验代码写入 SHA 清单。
- 每臂 2 个 epoch、每 epoch 512 次更新，合计 1,024 次；B4、无增强、workers=0，
  两臂共用每个实际 batch。每 epoch 随机种子为 0、1，数据加载器同种子。
- fresh AdamW，lr=1e-5，weight_decay=.0005，clip_norm=.1；沿用原生损失及系数。
  不继承旧 optimizer，不进行 epoch、学习率或损失扫描。
- 起点及终点各对完整 holdout 评估一次，B16、seed=1000、workers=0。
  起点 B 的记录必须与 A 完全相同；不中途查询质量决定是否延训。
- 训练前使用首个 fit batch 进行有限梯度检查，0 次 optimizer 更新；零输出矩阵使
  点编码器首次梯度为零是预期行为，其输出矩阵应有非零梯度。此前固定扰动预检已确认
  点编码器可获得非零梯度。

## 预先固定的决定规则

首先验证文件、输入点 hash、REC 框/分数、Query 选择、冻结状态、训练行顺序、
每臂更新次数与 optimizer 状态。任一失败均不得按正常性能结果解释。

质量通过要求：B 终点同时相对 A 终点、受保护原生起点满足：

1. 原生选中 Mask 的平均 IoU 至少增加 .002，即 **0.2 个百分点**；
2. Mask@0.25 命中数不下降；
3. Mask@0.50 命中数不下降。

阈值沿用原 evaluator 的严格 `IoU > threshold`。分别报告修复、破坏、净变化，
并以 scene 为聚类单位做 2,000 次配对 bootstrap。置信区间是报告项，不能用于
事后改变以上门槛。原生控制即使更好，也不自动升级受保护模型。

另外记录下列条件 Mask 指标，作为机制诊断，不另设事后质量门槛：

- 当前合法 REC Query 的 Mask，固定其 Query 与框；
- 起点合法最佳框 IoU>0.5 的固定样本集合上，该最佳框 Query 的 Mask。

第二项仅用 GT 建立诊断集合和 Query，不参与训练候选选择或部署。不能把“最佳框”
称为已经逐条验证的正确物理实例。若总体收益与条件 Mask 结果不一致，应缩小机制
结论，不能仅凭总体均值宣称恢复了局部形状。

## 执行、审计与后续边界

入口 `scripts/run_nr3d_point_detail_pair.py`；终态复算
`scripts/summarize_nr3d_point_detail_pair.py`。保存起终逐行输出、16/19 个参数张量及
对应 optimizer 状态、输入清单、训练顺序和运行回执，不覆盖 parent。

先通过原服务器 Python3.7/PyTorch1.10 的 CPU 检查，再独占现有 GPU 锁启动。
根据实际 baseline 和训练速度估算完成时间；接近预计阶段结束时以 240 秒间隔观察。
质量失败则封存该固定版本，不自动续训或调门槛。通过后才准备独立正式配对验证。

REC 路径冻结，因此本实验本身不能完成 Nr3D REC>60% 的目标。正式三数据集目标继续
保留；后续身份推理需要真实新视觉证据或实际任务记忆读取，不能仅添加可被 bias
吸收的任务常量。Sr3D 的受保护权重备份仍需恢复。
