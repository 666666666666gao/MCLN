# PV-Ground 稀疏体素到堆叠邻域的批次顺序修正

## 实际问题

初始固定8表达（均为scene0003_00）在同种子、同权重、同输入重放时，骨干point_features已不同，早于Gumbel。两独立进程各三次完整前向退出0；同进程重置随机状态仍不能消除差异。

进一步两次只读骨干前向发现：conv2开始，spconv输出坐标行在8个batch之间交错；conv2首遍252256行中220502行不属于按计数划出的预期batch连续段。按batch/z/y/x坐标在CPU对齐后，conv2/3/4/out的特征逐元素相同；VFE、BEV、原始点聚合和x_conv1聚合也相同，x_conv2/3/4的VSA聚合不相同。

固定OpenPCDet的pointnet2_stack/src/ball_query_gpu.cu按xyz_batch_cnt的前缀和移动xyz指针，并在连续段内搜索。原PV-Ground的aggregate_keypoint_features_from_one_source只统计batch计数，没有把稀疏坐标/特征行按batch重排。实测输出违反了该算子输入约定。这是当前移植组合的实际接口错误，不泛指spconv所有算子不正确。

## 最小修正

只修改独立PV-Ground副本的models/pv_utils.py：在每个多尺度稀疏源进入VSA前，按batch/z/y/x整数键排序，坐标和特征使用同一索引。批次连续是正确性要求；批次内坐标顺序固定，使first-nsample邻域选择不依赖spconv行排列。保持坐标—特征关联、原始体素集合、回归/文本/Mask头与参数数目。

原runtime和历史负结果不修改；无依赖升级或CUDA重编译。修正后源码SHA33279bc4e0302250025eb963f956f164cbe3f9b265ac57d9d4826abf6c370810。预训练仍为官方epoch81 SHA6f24c67cc3409f44befdef188f14383497a824d8ab309b8fd572a999ae8bdec3。

## 执行顺序与不变项

1. 用原冻结输入、seed2027、两个进程各三次完整前向复查，分别报告同进程重置种子和跨进程数值/选择差异；随机状态推进控制单独报告。此验证不声称完整6887可复现或正式性能改善。
2. 通过后，从相同官方预训练进行一次修正接口的ScanRefer固定训练。与detalign版本相比仅模型VSA接口变化，保留已验证的检测框增强顺序修正。
3. 仍29778 fit/6887模块留出、相同scene划分、batch8、seed2027、3723更新、lr及backbone lr均1e-5、原生GT损失、最后一步终点、bbs为主；不扫LR、损失、seed或epoch。先执行真实batch8容量前向/反向并恢复原权重，随后完整起点评估及训练。
4. 独立CPU重算起点/终点REC计数及转移，终点相对本轮起点双REC不退化才运行既定9508正式比较。正式Scan达到5572/4797及Mask58.70/50.70/44.72底线后尽快Nr/Sr，Nr/Sr Mask不设门。

这不是再次尝试已封存的局部读取、Gate或末端打分头；它修正新找到的模型输入契约错误。旧两次训练结果保持原样，但不能再把它们当作正确批次邻域条件下的完整PV-Ground微调结论。排序修正可能改变预训练输入分布，性能收益没有预先保证。

预计一次训练加起终点评估约3小时，前15分钟左右检查起点/容量，之后靠近预计终态再查。后台依赖检查每300秒。只保留必要权重，不复制预训练；原始重放tensor留服务器，不进入Git。

## 修正后的重放与执行判断

14:20:54六次前向完成，两个进程内重置种子的全部记录tensor逐元素相同。跨进程并非逐位一致：骨干最大差1.43051147e-6、最终中心3.98159027e-5米、尺寸4.67181206e-4米、raw bbs分数8.44597816e-5；8条raw选择全部相同。原进程间骨干最大差0.591557、中心1.116519米、尺寸5.617179米。不能由8行推断全量命中完全一致。

本计划初稿曾要求跨进程浮点逐位一致；该草案在重放已经启动后整理，并非预注册性能标准，实际没有满足，保留此事实。执行时不把这个额外要求当成用户提出的晋级门：已观测的批次顺序错误需要修正；剩余数值误差据实报告，不能伪称完全确定性，也不能抵销任何REC退化。后续保持原有独立计数和正式性能门槛，不通过重复随机运行挑结果。一次固定Scan训练将检验修正接口后的实际性能。
