# F：原生 bbs 的 root 匹配候选竞争

状态：实现与预检阶段；尚无训练终态或正式成绩。

依据：固定训练128场景中，宽松错误14条有13条最贴近其他同类实例；严格错误22条另有8条最贴近root但范围不过线，且8条均存在合格替代框。最大框重叠仅为几何代理。原生CE方向诊断没有证明CE错误，因此保留原生监督，测试辅助竞争的独立增量。

## 唯一训练改动

保持D的完整预训练PV网络及任务读取，不沿用失败E的视觉冻结。每次真实原生criterion记录7次Hungarian匹配，使用第二次（last_）中target=0的唯一root匹配p。

部署bbs分数s严格复用现有概率求和：root正词二值图＋modifier/pronoun/relation权重－other_entity权重。对t=0.25、0.50分别取IoU<=t中最高分的负候选n；只有IoU(p)>t且负候选存在时启用。

L_t = relu(stopgrad(IoU(p)-IoU(n)) + s(n)-s(p))。

最终L=L_native+(L_25+L_50)在2×batch槽位上的均值，系数1，不扫描margin/温度/权重。IoU、选样全部detach；原生回归继续训练。无合格匹配时仅由原生损失训练，不改选未匹配正候选，不把重复好框全标为正例。新增监督不进入模型forward，GT不进入推理输入。无新增参数、质量头、Gate、蒸馏或部署规则。

## 控制与预算

- 控制复用D：相同官方epoch81父、相同923616参数读取结构、820允许训练张量、相同输入顺序、数据修复、增强和seed2027。
- 新F从官方父和零输出读取初始化，不能从失败D/E终点续训后声称同起点对照。
- 固定batch8、LR1e-5、原优化器与裁剪；29778fit行一次、3723步；不选中途权重、不加epoch。
- 6887模块留出、bbs主输出、bbf诊断；比较真实自身起点及D终点。起点是否相同须以导出核验，不先声称字节等价。
- 终态完整性和主REC筛选后才接9508正式；正式两阈值5572/4797，Mask仅记录。达到正式保护线后尽快Nr/Sr，不等59/51。
- 估计训练与两次留出评估约2小时，依据D/E实测；真实吞吐后更新ETA。轮询180—300秒。

## 执行顺序

1. CPU行为检查：梯度提高原生匹配正例并降低高分错误候选；未匹配好框不被该项奖励；无有效正/负时零损失；几何标签不反传；带负跨度的部署分数一致。
2. 真实原batch8前向/原生匹配/联合反向，0optimizer，验证新增项有限、实际有非零logit梯度；恢复全部起点状态。这里只是工程预检。
3. 复用既有环境。训练启动前确认GPU锁、磁盘容量及唯一队列，固定终态审计与REC-only正式接续。当前剩余空间有限，必须先落实检查点保留预算，不能以清理为名删受保护权重。
4. 运行固定F，与已有D对比；失败则保留真实负结果，不立即扫超参数。

主要风险：额外排序项与原生任务共享参数，局部梯度方向不等于泛化收益；一对一正例虽避免重复正例冲突，却可能对当前匹配框质量敏感。实验检验的是直接部署竞争监督，不宣称通用排序损失为新颖结构，也不预先宣称解决语义身份或梯度冲突。
