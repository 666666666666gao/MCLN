# C：保留内容并提供实际观测状态的分源读取

固定研究起点为完成的普通分源B（主REC6136/5481，自己的变化-11/-68，正式跳过）。C不加载B终点，使用同一官方ScanRefer epoch81父权重、正确mesh/框增强/VSA排序、seed2027、batch8、29778条fit顺序和3723次更新预算。预设主输出bbs，bbf只诊断。原生GT损失、全局路径、语言和对象路径、匹配、Box/Mask头不改。

## 唯一新增机制

在B的六路融合前特征和FPS关键点坐标旁保留实际观测描述。每路新增零初始化Key与Value线性映射；表达条件已通过当前Query的原文本交互进入读取，未额外声称完整文本token交互或双任务读取。所有状态保留，不按空标记删除特征或候选。末端原残差输出仍零初始化。

Key/Value各6个参数矩阵，不含bias，共43200个参数；C读取总757728参数、36个state tensors，B原24个键与初值不变。额外参数直接用零tensor创建，不改变B初始化随机流。没有新损失或GT输入，没有新的随机dropout、采点或半径。

## 状态与真实计算位置

1. raw/conv1/conv2/conv3/conv4：每个既定半径分别6维：实际ball_query非空；去填充后选中索引数/nsample；所选独立索引的最小/平均/最大距离除以半径；选中数是否达nsample上限。两个半径12维，再附加FPS位置是否在体素化范围内，共13维。最后一位对raw表示共享体素范围状态，不是raw路径失效标记。
2. CUDA当前核依次扫描源位置并以第一个索引补齐空槽，达到nsample即停止。因此这些数值描述已选的独立支持索引，不能称为半径内总点数、全局最近距离或目标点数量。空组直接使用实际empty_ball_mask，所有统计置0，has_support=0消除与真实零距离的混淆。
3. BEV单独10维：FPS位置是否在体素化范围内；XY是否处于无需clamp的完整插值域；四个实际clamp角点的encoded sparse column占据标记；四个与原插值相同的权重。占据来自encoded_spconv_tensor.indices，含卷积感受野，不冒充直接原始点观测。重复角点只作角点标记，不相加为独立计数；域外权重按原实现保留，不修改插值。
4. 状态位于真实FPS关键点、来源和半径，不是连续Gumbel Query中心或最终Box中心的覆盖。没有GT instance/anchor/IoU进入状态提取。

`ObservedQueryAndGroup`保留上游ball_query、grouping_operation、相对坐标、原MLP前空组清零等既有行为，只同时记录实际索引与empty结果。不做此前失败的池化后清零。VSA的MLP/BN/激活/池化结果及非零先验保持。
